# ADR 0005 — LLM 调用上下文记忆与分层压缩

每次调用 LLM（自动纪要、重新生成、Meeting Q&A 等）都通过统一的 **Context Packer** 组装提示，保证**有本场上下文**。采用 **分层：重要信息全量，次要信息可压缩/摘要**，避免整场原文每次原样塞满窗口，也避免「一刀切摘要丢待办/争议」。

- **Status:** Accepted  
- **Date:** 2026-07-19  
- **Deciders:** 人（产品/工程）

## Context

产品含 Auto Minutes 与多轮追问。长会 Transcript 可达数万字，API 有上下文上限且计费按 token。用户要求：**简单实用的记忆**——每次调用带上下文；**只压缩不重要的**，重要仍全量。4C4G 上不做重型向量库亦可工作。

## Decision

### 1. 每次 LLM 调用必带「本场记忆包」

至少包含（按优先级，能放下则全放）：

| 层 | 内容 | 压缩策略 |
|---|---|---|
| **L0 系统** | 角色、输出 schema、安全与语言 | 固定短模板，不压 |
| **L1 钉选全量** | Minutes 头、争议点、Action Items、用户改过的字段、本轮用户问题 | **永不摘要替换**（除非用户清空） |
| **L2 结构化纪要** | 关键议题等已生成 Minutes 正文 | 优先全量；超限时按章节裁，**先砍时间轴长段** |
| **L3 对话记忆** | 本场 Q&A 最近 N 轮 | 最近 K 轮全文；更早轮 **滚动摘要**（一条 bullet 列表） |
| **L4 转写** | Transcript（Speaker+时间+文） | **默认不整场全量**；用检索片段（见下）或章节摘要 |
| **L5 跨会** | 其他 Meeting | **P1**；首版不做或仅手动引用 |

### 2. 简单压缩机制（非重 RAG 也可）

**A. 预算制 packing（P0）**

1. 设定 `max_context_tokens`（可配置，按模型）。  
2. 按 L0→L1→L2→L3→L4 装入；每层装完再装下一层。  
3. 超预算时：  
   - L4：只保留 **与当前问题/生成任务相关的片段**（关键词/简单打分取 Top 段），其余用 **Transcript 压缩摘要**（可缓存）。  
   - L3：旧轮合并为「对话摘要」。  
   - L2：去掉低优先章节（时间轴细节先于议题/待办）。  
4. **L1 永远最后被砍**；若仍超限，报错/拆分任务，而不是静默丢掉待办。

**B. Transcript 压缩摘要（可缓存）**

- 转写成功后（或首次需要时）生成并落库 **`TranscriptDigest`**：按时间片/话题的短摘要 + 可选关键句时间码指针。  
- 自动纪要：L1 空时以 Digest + 必要时抽样原文段生成 Minutes。  
- 追问：Query → 选相关原文段（时间码命中 / 简单词重叠）**全量**进 L4 片段；Digest 作全局地图。

**C. 不做首版**

- 全库向量记忆、GraphRAG、跨会自动画像。  
- 用「只塞最近 2k 字原文」而无 Digest（长会会丢头）。

### 3. 持久化

- 本场：Transcript、Minutes、Q&A 消息、Digest、用户编辑 — 进 Store（倾向 SQLite + 文件）。  
- Packer 只读组装，不把「压缩丢弃」写回毁掉 L1 真源。

## Consequences

### Positive

- 追问与再生成始终「记得」本场待办/争议。  
- 长会可控成本与长度。  
- 实现路径清晰，无强制 GPU/向量库。

### Trade-offs

- Digest/片段检索质量一般时，追问可能漏原文细节 → 应用可提供「引用原文段」或扩大 TopK。  
- 需维护 token 预算与缓存失效（用户编辑 Minutes/Transcript 后 Digest 标记脏）。
